## Findings

### F1 — `client_control_mode` value is `"1"`/`"0"`, not `"1"`/`""`
- Severity: P1
- Category: spec-inaccuracy
- Axis: A
- Spec location: SPEC.md:1155 (§21 Format Variables table)
- Source location: format.c:1424-1432 (`format_cb_client_control_mode`)
- Claim under audit:
  > | `client_control_mode` | `"1"` or `""` | Whether client is in control mode |
- Reality in source of truth:
  > ```
  > format_cb_client_control_mode(struct format_tree *ft)
  > {
  > 	if (ft->c != NULL) {
  > 		if (ft->c->flags & CLIENT_CONTROL)
  > 			return (xstrdup("1"));
  > 		return (xstrdup("0"));
  > 	}
  > 	return (NULL);
  > }
  > ```
  > (format.c:1424-1432). For a non-control client the callback returns the string `"0"`, not the empty string. The empty/absent case is `NULL`, which only occurs when there is no client (`ft->c == NULL`).
- Fix direction: correct-spec
- Recommendation: Change the Value column to `"1"` or `"0"` (with `""`/absent only when no client). The current `""` misstates the false-case wire value.
- Test impact: none (not asserted in tests/integration/client.test.ts).

### F5 — §23.1 "Synthetic Events" is library content carried in the protocol spec
- Severity: P3
- Category: library-content-in-spec
- Axis: C
- Spec location: SPEC.md:1219-1233 (§23.1, tagged `(library)`)
- Source location: src/connection-state.ts (library types: `connection-state`, `reconnected`); no tmux wire origin
- Claim under audit:
  > ### 23.1 Synthetic Events (library)
  > The following events are emitted by `TmuxClient` itself and are NOT parsed from tmux wire output. They carry lifecycle state synthesized as the underlying transport transitions. See `src/connection-state.ts` for type declarations.
- Reality in source of truth:
  > These events have no emit site anywhere in the tmux C source — they are a library superset (`connection-state`, `reconnected`) over the wire protocol. SPEC.md is documented as "the tmux wire control-mode protocol"; library-synthesized events belong in IMPL.md / JSDoc, not in the protocol message reference.
- Fix direction: relocate-to-IMPL/JSDoc
- Recommendation: Relocate §23.1 to IMPL.md (or `connection-state.ts` JSDoc). The subsection is already self-tagged `(library)`, so this is a low-cost move; leaving it under "§23 Complete Message Reference" risks a reader treating these as wire messages. Not a "remove from library" recommendation — the events are legitimate library API.
- Test impact: none.
